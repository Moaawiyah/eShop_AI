# ADR-0010: OpenAPI Type Generation with a Thin Hand-Written Client

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-11-28 |
| Deciders | Project owner (accelerated M1 Batch A authorization) |
| Jira | SHOP-015 |

## Context

The frontend must call the backend only through one typed API client whose
types come from the FastAPI OpenAPI document, never from hand-written
duplicates (FR-PLAT-015, AC-048). UD-14 left the generator open. The client
must also own credentials, the CSRF header and problem-details error
normalization, which no generic generated client does the way this project
needs (ARCHITECTURE sections 3.8 and 4.3).

## Decision

Types are generated by **openapi-typescript** (types only; a development
dependency) from the committed OpenAPI document. A thin, hand-written client
over `fetch` uses those types.

- `backend/scripts/export_openapi.py` writes a deterministic
  `frontend/src/lib/api/openapi.json`; `schema.d.ts` is generated from it.
  Both are committed.
- `npm run generate:api` regenerates both; `npm run check:api` regenerates
  into a temporary directory and fails when either committed file differs
  (the AC-048 check; CI wiring arrives with SHOP-017).
- The client derives request and response types from the generated `paths`
  and adds `Accept`, the CSRF header for unsafe methods, timeouts and
  `ApiError` normalization.

## Alternatives Considered

| Alternative | Reason not chosen |
|---|---|
| openapi-fetch | Small, but adds a runtime dependency; our client must own credentials, CSRF and error normalization anyway |
| orval, openapi-generator, hey-api | Generate whole clients; heavier and more churn for little gain |

## Consequences

**Positive**

- Types only: no generated runtime code and no runtime dependency.
- Drift between backend and frontend is caught by a deterministic check.
- Full control over cross-cutting client behavior.

**Negative**

- Generation needs `uv` and the backend environment.
- Response bodies are typed but not validated at runtime; only error
  bodies, which are untrusted, are validated.
- The client's helper types are maintained by hand (small).

## Reconsideration Conditions

Revisit if the hand-written helper types grow burdensome, or when runtime
validation of success responses becomes a requirement.
